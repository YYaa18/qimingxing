# Live Line + Workspace 设计规范

| 项目 | 内容 |
|---|---|
| 状态 | 已确认，进入开发 |
| 日期 | 2026-11-25 |
| 适用范围 | Quick Entry 对话呈现、工作区窗口、任务/通知交付 |
| 非目标 | 聊天记录列表、通用 Agent 气泡流、3D/画布工作台 |

---

## 1. 核心原则

1. **Quick Entry 只负责“现在”**：一句输入、一句最新回答，不堆叠历史。
2. **Workspace 负责“曾经”**：回答、任务、产物、日记、审批记录全部进入工作区。
3. **声音优先**：呼吸边框代表启明星正在思考/说话；后台任务用语音确认 + macOS 通知交付。
4. **大字、少元素**：回答默认 16pt（设置可选 14/16/18/20），输入 22pt，完整展示；没有头像、气泡、消息列表。
5. **新内容覆盖旧内容**：新回答替换当前回答，不追加。

---

## 2. Quick Entry（Live Line）

### 2.1 尺寸

| 状态 | 宽度 | 高度 | 说明 |
|---|---|---|---|
| Idle | 760 | 112 | 单行输入 + footer |
| Thinking | 760 | 236 | 状态行 + 呼吸边框 |
| Responding | 760 | 200–520（随内容） | 完整回答 + 呼吸边框 + 工作区链接 |
| Done | 760 | 200–520（随内容） | 回答保留，边框平息 |

- 圆角：24pt continuous。
- 材质：`.popover` + `behindWindow`；无窗口交通灯，Esc 关闭。
- 输入栏：68pt 高，22pt 字号。
- 展开高度由固定 696pt 宽度下实测的完整回答高度决定：短回答收紧到内容高度，最长 520pt；超过后舞台内滚动。
- 聊天区高度与侧翼解耦：侧翼只在外层施加 `max(chatHeight, 430)`，关闭后精确恢复 `chatHeight`；侧翼/窗口动画期间不重新测量。
- 打字机结束后再用真实渲染内容高度做一次最终校正，取固定宽度测量与最终测量的较大值，避免最后一行被裁。
- 回答区不自动滚到底部：始终从第一行开始展示。
- 短回答使用普通 VStack，不创建 ScrollView，因此不会出现任何滚动条。
- 超过设置的行数阈值（默认 30，可在 5–80 间调整）后，面板固定在阈值高度，回答区切换为可滚动；此时显示滚动条。
- 阈值同时受屏幕可用高度约束，避免窗口超出屏幕。
- 呼出面板时控制器优先恢复上一次的 `chatHeight`，不再用 520 兜底覆盖；每次呼出通过 layoutToken 让视图主动上报一次。
- 情绪：Brain 的 avatar.state 情绪事件在输入栏底部显示为原生情绪徽章，不进入朗读文本。

### 2.2 状态机

| 状态 | 触发 | 画面 |
|---|---|---|
| Idle | 无回合 | 输入行 + 模型/看屏/发送 |
| Thinking | 已提交，未收到首个文本 | 旋转点阵地球 + “正在思考 / 正在看屏 / 正在调用工具” + 呼吸边框 |
| Responding | 流式文本到达 | 打字机回答（默认 16pt）+ 呼吸边框 |
| Done | 回合结束 | 回答保留，边框平息，工作区链接 |
| Error | 回合失败 | 一行错误 + 重试提示 |

### 2.3 排版

- 回答：正文默认 16pt、行距 3，可在设置中选 14/16/18/20；代码块约 0.72×正文的等宽卡片；不设行数上限。
- 输入：22pt；占位符由 `NSTextView` 自身绘制，与光标同基线。
- 辅助：12pt secondary。
- 工作区链接：12pt，“完整记录已放入工作区 →”。
- 回答完成后底部提供复制、赞、踩：复制完整回答正文；赞/踩只对最新一轮生效。
- 不使用气泡、头像、消息 meta、时间戳列表。

### 2.4 呼吸边框

- 位置：整个对话 body 的外缘，不做独立波浪条。
- 形态：1.8pt 圆角描边，`AngularGradient` 由白色高光与 accent 组成，约 2.8s 绕行一周。
- 性能：静态渐变由 Core Animation 旋转，遮罩裁成圆角环，不逐帧重建 SwiftUI body，也不使用模糊光环。
- Idle / Done：完全隐藏，只保留 1px hairline。
- Thinking / Responding：激活并持续绕行；工具调用或流式输出时保持同一节奏，不闪烁。
- Reduce Motion：角度固定为静态高光，仅做淡入淡出，不旋转。

### 2.5 加载指示

- Thinking 状态在状态文字左侧显示点阵地球，约 2.6s 转一圈；Reduce Motion 时静止。
- 工作区中运行中的任务行也使用同一地球指示器，替代静态圆点。
- 不使用第三方动画库；Canvas 绘制经纬点阵，约 24fps。

### 2.6 覆盖与打字机

- 新回合：旧回答 180ms 模糊上移淡出，新回答 220ms 从下方 8px 升起。
- 打字机：约 18ms/字符；Reduce Motion 直接显示全文。
- 新问题可随时打断当前回答（barge-in）。

### 2.7 长回答

- 回答完整展示，不截断、不加省略号；正文与代码块一并保留。
- 文本宽度固定为 ScrollView 的可视宽度，禁止无界宽度导致中文长行被横向裁切。
- 超出可视区时在舞台内滚动：打字机跟随底部；输出结束后回到顶部，便于从头阅读。
- 下方始终提供“完整记录已放入工作区 →”。
- 舞台只保留最新一轮，不做历史堆叠。

## 3. 任务与通知

- 派发后台任务：Live Line 显示“已交给后台：…”，2s 后收回。
- 语音确认：“好的，我会在后台处理，完成后通知你。”
- 完成：语音摘要 + macOS 通知，动作“打开工作区”。
- 进度不在 Quick Entry 展示；工作区任务卡保留 2pt 进度与步骤。
- 审批：原生 Sheet；用户离开时使用通知动作。
- 朗读：菜单栏与设置均提供「朗读回答」开关；关闭后立即停止当前播报并静音后续回答，语音输入不受影响。

## 4. Workspace（工作区）

### 4.1 默认形态：从聊天框长出的侧翼（Wing）

- 从对话框右侧展开 380pt 宽的简易工作区，与主聊天框组成一个连续的圆角体；放不下时整体左移。
- 侧翼有自己的设计，不复用三栏工作区：
  - 头部 52pt：工作区 · 今天 N 轮 + 拆分按钮 + 收起按钮。
  - 分段：对话 / 任务 / 产物，带数量。
  - 对话：最近 3 轮，时间 + 用户问题 + 回答摘要（最多 4 行）。
  - 任务：状态点、标题、状态/步骤、2pt 进度。
  - 产物：文件名 + 路径，点击 Quick Look。
  - 底部：轮数/任务/产物统计 + “独立窗口 ↗”。
- 侧翼展开时对话框最低高度 430pt；对话内容仍按内容自适应。
- 拆分按钮：收起侧翼、恢复 760pt，并在附近打开 920×620 独立工作区。
- 助手工具 `open_qimingxing_ui`：
  - `open_workspace`：面板可见且已有对话 → 展开侧翼；否则打开独立窗口。
  - `detach_workspace`：收起侧翼并打开独立窗口。
  - `close_workspace`：收起侧翼，聊天区高度保持不变。
- 无对话时打开工作区不展开空侧翼，直接给独立窗口。

### 4.2 独立窗口

- 920 × 620，原生窗口，可缩放/关闭。
- 三栏：过滤器（190）｜时间线（300）｜详情（剩余）。
- 打开方式：菜单栏“打开工作区”、Live Line 链接、通知动作。
- 停靠：优先在对话框右侧/左侧/下方/上方寻找完整可见的位置；若居中时放不下，对话框自动侧移让位，工作区贴到空出的一侧。面板未显示时居中打开。
- 关闭不退出应用；数据保留。

### 4.3 工作项

| 类型 | 来源 | 内容 |
|---|---|---|
| 对话 | 当天所有回合合并 | 按时间排列的问答记录（问题 + 完整回答） |
| 任务 | 后台任务 | 标题、状态、进度、步骤、结果、产物 |
| 产物 | artifact capsule | 标题、路径、打开/预览/复制 |
| 日记 | 当天聚合 | 当天回答/任务按时间聚合（后续） |

- 对话按自然日合并为一条“当天对话”，不按单次提问拆条；任务、产物各自独立成卡。
- 对话详情是连续问答记录（问题 + Markdown 回答），按时间正序，默认定位到最新一条。
- 不使用聊天气泡；时间线行是“工作项”，不是消息。
- 同一 turn 在存储层仍保留一行，流式更新覆盖；合并只发生在展示层。

### 4.4 过滤器

- 今天
- 全部
- 对话
- 任务
- 产物

### 4.5 时间线

- 行高 54；时间（HH:mm）+ 类型图标 + 标题 + 摘要。
- 对话行：标题为最近一次问题，摘要为“N 轮 · 最新回答”；任务/产物行维持单条。
- 按日期分组，日期标题：今天 / 昨天 / MM月dd日。
- 搜索：标题、问题、正文、路径。

### 4.6 详情

- 对话：日期标题 + “N 轮” + 逐回合问答；每轮都包含用户问题与回答，问题带时间与左侧竖线，回答为完整 Markdown；可复制。
- 任务：状态、进度、当前步骤、结果、产物操作。
- 产物：路径 + Quick Look / Reveal / Copy。

### 4.7 用户问题镜像

- `output.turn_start` 新增 `user_text` 字段，Brain 将用户输入镜像给所有 body 客户端。
- 原生壳在回合开始时补一条 user 消息（若本地已有同一 turn 的 user 消息则跳过），因此工作区/侧翼能看到“问题 + 回答”的完整对话。
- 该字段为协议可选增量，旧客户端忽略即可。

### 4.8 助手控制组件

- 新增 safe 工具 `open_qimingxing_ui`：`open_workspace` / `open_settings` / `open_quick_entry`，无需审批。
- 执行链路：Brain 工具 → `ui.command`（target=shell）→ 原生壳执行；打开工作区时沿用面板锚定停靠。
- 系统提示明确：工作区是应用内组件，禁止用 shell / Finder / 文件搜索去推断路径。

### 4.9 持久化

- Shell 本地 JSON：`~/Library/Application Support/Qimingxing/workspace.json`。
- 0600 权限；写入防抖 0.5s；最多保留 500 条。
- Brain/SQLite 仍是会话与记忆的事实源；Workspace 是本地工作视图，后续可同步 Markdown/Wiki。

---

### 4.10 反馈与价值评测

- `POST /api/feedback`（仅 localhost）接收 `turn_id / rating(up|down) / profile / prompt / answer`。
- 写入记忆库 SQLite 的 `message_feedback` 表（auto-increment `feedback_id`、`turn_id`、`session_id`、`rating`、`profile`、`prompt`、`answer`、`source`、`created_at`）。
- 表由 `CREATE TABLE IF NOT EXISTS` 在启动时自动补齐，已有数据库无需手动迁移；`turn_id` 与 `created_at` 建索引，便于按回合/时间检索并与 `messages` 关联。
- 当前用于沉淀真实偏好样本；后续可接入排序/评测与技能蒸馏，不在本轮自动改变回答策略。

## 5. 验收标准

1. Quick Entry 无历史列表、无气泡、无右侧预览；只显示最新回答。
2. 输入光标与占位符同一基线。
3. Thinking/Responding 呼吸边框激活；Done 平息；Reduce Motion 降级为静态高光。
4. 新回答覆盖旧回答，旧内容不堆叠。
5. 回答完整显示，不出现省略号；长回答在舞台内滚动，工作区保留完整记录。
6. 后台任务完成时语音 + macOS 通知；工作区任务卡更新。
7. 工作区按天合并对话，任务/产物独立分类；跨重启保留全部内容。
8. 深浅色、IME、Esc 关闭、焦点归还全部正常。
9. `pytest` 112 通过；`swift build` 0 warning；无 Luminare。
